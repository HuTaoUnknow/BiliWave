# 已有版本检测、覆盖升级与单独安装

从当前工程生成的后续安装包使用同一套安装选择逻辑，加装版与简装版分别识别。

## 交互流程

安装程序检查当前用户与系统级的 Windows 卸载注册记录（32 / 64 位视图），识别本版的原始安装标识及独立副本标识，同时检查本版默认安装目录。不扫描整个磁盘，也不会读取其他 Windows 用户的私人注册表。失效记录没有对应 `BiliWave.exe` 时忽略。

找到同版已有安装后，先出现选择页：

- **覆盖升级所选版本**：从列表选择已有副本，显示名称、版本及目录，沿用该副本原目录、快捷方式名称与卸载标识；更新程序文件，保留 `data` 中的乐库和设置。不先卸载旧版。
- **单独安装，保留已有版本**：生成不与已有副本重复的安装标识、版本化目录和快捷方式名称，独立保存数据并单独卸载。该副本也会被后续安装包识别，可以再次选择覆盖升级。

选择页不默认勾选覆盖。取消向导不会安装。单独安装要求新目录或空目录，拒绝复用已有文件 / 乐库；覆盖模式不能改到另一目录。手动选择含有未注册 BiliWave 的目录时会再次询问；标准便携版通过 OCR worker 区分加装 / 简装，拒绝两版混装。

机器上存在的其他版本不会因一次覆盖被删除。升级不改写歌曲、歌词、草稿或数据表结构；实际数据保存仍由应用控制。卸载继续保留用户数据。运行中应用的文件占用由原安装程序机制处理，需要时应先从托盘退出。

默认按当前用户安装；系统级版本需以管理员身份使用 `/ALLUSERS` 安装模式升级。用户级版本应使用默认用户模式，两种注册范围不能混用覆盖。

## 自动部署参数

普通用户使用安装向导即可。静默部署在检测到已有版本时必须明确给出选择，不会默认覆盖：

```text
/INSTALLMODE=upgrade /UPGRADETARGET="已有版本的完整目录"
/INSTALLMODE=separate
```

只有一份同版安装时，`upgrade` 可省略目标；多份时必须指定。`separate` 可通过 `/DIR=` 指定新目录；否则自动选择独立版本目录。参数不允许绕过目录冲突与版本类别检查。

## 实现与验证

`packaging/BiliWave.iss` 仍是唯一打包入口；`packaging/InstallChoice.iss` 统一生成安装计划，控制 AppId、目录、快捷方式及卸载名称。原始 Full / Lite GUID 保留。Inno Setup 通过 AppId 识别卸载项及安装日志，因此独立安装必须使用独立 AppId，不能只改目录。[Inno Setup AppId 文档](https://jrsoftware.org/ishelp/topic_setup_appid.htm)

运行 `scripts/verify-install-choice.ps1`，使用小型测试载荷、项目 `.cache` 目录及仅本次 GUID 命名的 `HKCU\Software\BiliWave\InstallerTests` 注册表夹具。测试完成清理该测试注册表，不修改真实安装注册、快捷方式或实际乐库。生产打包不会启用 `UpgradeTestMode`。

两版均已验证：生产分支编译、新装、多副本发现、无选择拒绝静默覆盖、目标不明确拒绝、更新程序同时保留数据与设置、独立身份避重、独立副本再次升级、目录冲突与跨版本拒绝，以及卸载保留数据。原生控件坐标验证选项与下拉框不重叠且不超出页面；交互截图因窗口授权超时未取得。详细结果见 [installer-choice-validation.json](installer-choice-validation.json)。

本轮同步包含安装脚本与验证报告，不替换此前 GitHub Release 已发布的安装包；后续重新打包即带此流程。
