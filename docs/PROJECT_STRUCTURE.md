# BiliWave 项目结构与整理方案

编写日期：2026-11-01。此文档在本轮代码整理前建立，先记录审查结果和目标结构；实施完成后追加验证结果。两种发行版共用工程，通过功能开关区分：加装版保留字幕 OCR，简装版保留在线歌词匹配；本轮不重新引入音频听写或对齐模型。

## 审查结果

| 区域 | 当前问题 | 本轮处理 |
| --- | --- | --- |
| 播放模式 | `Sequential` 与 `ListLoop` 实际都消费队列、播完移除 | 统一为顺序播放；保留旧配置数字的读取兼容，随机与单曲循环不改 |
| 窗口组织 | `mainwindow.cpp` 2912 行，包含主壳、乐库、搜索、收录、工作台和设置 | 按页面拆成独立实现文件，继续共享 MainWindow 的明确接口 |
| 歌单卡片 | 已取消的小按钮仍有绘制、命中判断、工具提示、信号及可选开关 | 删除未启用的功能路径，统一两处卡片配置 |
| 控件创建 | 播放页与主窗口重复创建按钮、标签；多处重复拼接 URL 标记 | 集中到轻量 UI 辅助模块，图标与颜色仍由 Qt 绘制 |
| 构建 | 应用与多个界面测试重复编译相同实现文件 | 核心、服务、UI 分层复用编译产物；保持 Full / Lite 分开构建 |
| 歌单统计 | 两个页面逐张查询整首歌曲并求时长，乐库另行收集归属 | 数据层一次聚合歌单数量 / 总时长；单次查询归属 ID；列表查询只取显示所需字段 |
| 队列校验 | 每次乐库变化对每个队列项再次读取完整歌曲 | 一次读取有效歌曲 ID，支持重复队列项，仍更新名称与删除状态 |
| 播放歌词 | 每次位置更新读取歌曲 / 草稿；双语反复重放此前所有时间点 | 当前歌曲变化时缓存偏移与显示状态；播放时二分定位，不查询数据库 |
| 主题 | 仅蓝色、浅粉；配色分支不方便扩充 | 单一主题目录：大肥鱼、ChatGPT、Grok、Claude、浅粉玫瑰；统一背景、前景、强调色和图标前景 |

保留有实际使用者的接口。在线检索的单源兼容类和多源调度器职责不同，不能因为名字接近就直接删除；OCR 的 Python 图像、字幕分段、空格、语言模块也继续独立。联网仍按既有串行、限流、分批策略运行，不增加请求并发或自动重试。

## 目标结构

```text
src/
  main.cpp                启动参数、单实例指令、隔离验证入口
  window.h                主窗口接口与页面状态
  mainwindow.cpp          导航、主壳、服务连接、主题切换
  librarypage.cpp         乐库浏览、筛选、排序与歌单整理
  searchpage.cpp          在线搜索、分页、封面、收录队列
  workbenchpage.cpp       歌词草稿、时间轴、试听、裁剪与应用
  settingspage.cpp        分组设置与持久化
  playbackpage.cpp        播放浏览、消费队列与队列操作
  interaction.cpp         按键、焦点、外部文件拖入
  window.cpp              共享视图、菜单、窗口生命周期与歌词展示
  uihelpers.{h,cpp}       按钮、标签、共用图标、歌曲标题格式
  theme.{h,cpp}           主题目录、调色板与样式
  library.{h,cpp}         SQLite、歌曲与歌单、独立工作台草稿
  player.{h,cpp}          播放、音频输出、队列与播放模式
  lrc.{h,cpp}             LRC 解析、简繁转换、双语显示状态
  autoducking.{h,cpp}     自动降低音量
  services.{h,cpp}        本地导入、下载、歌词服务、导出
  searchservice.*         哔哩哔哩搜索
  streamservice.*         URL 音轨解析
  onlinelyrics.*          歌词源检索、排序、缓存、限流
  lyricworkflow.*         OCR 框选窗口、后台任务、结果队列
  desktopintegration.*   托盘关联能力、单实例、开机启动
  progressbar.cpp         屏幕顶部只读进度条
workers/                  Python 字幕处理模块
tests/                    核心、服务、界面、OCR 与媒体集成验证
scripts/                  构建、依赖准备、双版部署与安装包
docs/                     当前工程说明、操作说明、历史变更与验证证据
```

编译依赖方向：`bili_core → bili_services → bili_ui → 应用 / 界面测试`。UI 复用对象库，保留资源自动注册；服务使用静态库，非 UI 工具可以单独链接。数据与媒体目录不属于源代码整理范围。

## 兼容与行为约束

- 播放模式保留持久化编号：旧 0、1 都读为顺序，2 为随机，3 为单曲循环。下拉框通过条目数据映射，不能把下标当模式值。今后保存统一的顺序模式值。
- 蓝色主题的存储 ID `dark` 保留，显示名称改为“大肥鱼”；`pink` 保留。新主题使用独立 ID。配色为产品印象的自主设计，不宣称官方精确色值。
- SQLite 表结构、歌曲 ID、歌单成员、草稿、媒体路径和歌词原文不迁移、不重写。缓存只保存可从数据库或歌词重建的派生信息，并在原有变更信号上失效。
- 顺序 / 随机播放继续消费当前队列，不将播完的歌曲重新塞回；同一首歌仍可多次入队。单曲循环和手动下一首保留原行为。
- 快捷键、文件 / 文件夹导入、试听、裁剪、歌词空白状态、音频设备切换、托盘与自动消声需要回归验证。

## 效率验证与验收

1. 修改前后使用同一份隔离夹具测量歌单统计和歌词查找；报告规模、重复次数和耗时，不将编译提速说成播放性能提速。
2. 检查歌单刷新消除按歌单数量增长的完整歌曲查询；播放位置更新不读数据库，缓存双语时间轴与原算法逐时间点比较。
3. 构建 Full、Lite、Debug；运行与变更相关的核心、在线歌词、工作台、主题和媒体测试。界面测试串行执行，避免焦点互相抢占；联网服务使用本地夹具。
4. 各主题实际渲染并检查导航、按钮、队列、歌单、输入框、禁用状态和文字对比。浅色主题的强调按钮采用相匹配的前景色。
5. 更新 README、使用说明和本结构文档，记录实际改动与未纳入的建议。本轮只更新本地程序，不自动发布安装包或 GitHub。

## 实施结果

已按上述顺序完成结构文档、代码整理、主题扩展与验证。

- `mainwindow.cpp` 从 2912 行拆为 486 行主壳；乐库 298 行、搜索 387 行、工作台 1035 行、设置 649 行。MainWindow 接口保留，未引入额外页面控制器或新数据库层。
- 删除歌单卡片已取消按钮的绘制 / 点击 / 提示 / 信号 / 属性开关，删除从未使用的“下载本页”分支，公共按钮、标签、图标和 URL 标题格式集中到 `uihelpers`。
- 原顺序 / 列表模式合并，旧数字 1 兼容读为顺序；下拉框三个条目通过数据映射到 0 / 2 / 3。重复入队、消耗队列、随机排序和单曲循环通过回归验证。
- 歌单聚合、列表摘要、归属 ID 和队列有效 ID 查询已落地；切歌不重建浏览列表，避免乐库刷新重复重建队列。播放位置更新取消查库，双语显示缓存按歌词 / 繁简变化重建。
- 五种主题已经实际渲染；Grok / ChatGPT 的强调色使用深色前景，并补充深色勾选图标。旧蓝 / 粉配置 ID 不变。主题目录详见 [UI_THEMES.md](UI_THEMES.md)。
- Full 全部 7 组 CTest、Lite 全部 5 组 CTest 通过，Debug 构建通过。Full 的 4 个既有可选测试保持跳过，未把跳过项计为实际验证；外网检索仍按需显式开启。
- 600 首 / 24 歌单夹具的汇总中位数由 305.688 ms 降至 38.056 ms；600 事件、3000 次双语查询由 1150.392 ms 降至 0.964 ms。均为局部基准，不代表下载、OCR 或整个应用同比提速。见 [PERFORMANCE.md](PERFORMANCE.md) 和 [验证记录](REFACTOR_VALIDATION.json)。

当前改动已更新本地加装版、简装版与 Debug，未生成或发布安装包。SQLite 表结构与用户资料没有改写。本轮审查没有强行合并功能不同的联网调度器、OCR 模块，也没有去掉仍被测试或工具使用的兼容接口。
