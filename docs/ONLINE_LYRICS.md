# 在线歌词搜索（1.11.0）

两个版本共用同一个 Qt 网络检索器，不上传音频。在线版保留现成时间轴的搜索、预览、采用、试听和整首偏移，移除本机识别、模型配时、歌词导入和逐行编辑。

## 结果队列与繁简转换（2026-10-25）

工作台右侧的识别队列收集线上搜索返回的所有有效版本；加装版也收集屏幕字幕识别结果。在线版也显示该队列，但不开放本机任务或歌词编辑。没有时间轴的线上版本标记“仅文本”，可查看原文；当前两版均不含音频配时，纯文本不能直接作为时间轴应用。

每项显示当前运行期间递增的队列编号、获取方法、状态、来源；LRCLIB 结果另带来源记录号，悬停可查看来源链接和候选歌名、歌手。删除条目不会重排已有编号。采用或自动采用已入队的版本只更新其状态，不重复插入。工作台应用仅写入该歌曲的独立草稿；候选歌名和歌手仅供参考，不覆盖配置资料。URL 与本地歌曲均可配置，点击保存或导入乐库后才提交。

通用设置新增“繁体中文自动转简体”，默认勾选，切换立即保存。队列查看、工作台、桌面歌词和导出的 LRC 使用相同的转换设置；已有乐库歌词也适用。保留数据库和队列中的原始文本，关闭选项后重新查看即可恢复原文，不批量改写旧歌曲。手动改字后保存的内容以编辑结果为准。时间标签、换行、俄文及英文空格保持不变。

转换使用随程序内置的 [OpenCC 繁简字表和词组表](https://github.com/BYVoid/OpenCC/tree/ver.1.1.9/data/dictionary)，由 Qt 前缀树按最长词条匹配，词组优先，同一词条采用字典中的首选结果。词典约 39 KiB，无需新增语音模型、Python 包或联网请求。它是字词转换，不是歌词纠错或翻译。

此前直接使用 Windows `LCMapStringEx`，本机实测会漏转“後”，把“我在門後”输出为“我在门後”；现已更换转换实现，并加入截图原句、“乾淨 / 乾隆 / 乾坤”、双语文本和时间标签的回归检查。原始歌词仍保留，已有乐库无需重新下载或重新匹配。

## 检索

1. 清理视频标题中的音质、字幕等标签，优先提取《歌名》，保留俄文、中文等 Unicode 文本。
2. 根据歌名、真实歌手及已知时长尝试 LRCLIB 精确查询。
3. 回退到歌名＋歌手、仅歌名、关键词，以及必要时的原标题，最多五种查询，顺序执行，间隔 300 ms。
4. 合并去重后按歌名、歌手、时长及是否已有时间轴排序，不再只挑时长最接近的结果。界面显示匹配度和来源链接提示。
5. 仅歌名及歌手完全一致、时长差不超过三秒、且确有时间轴时自动采用；其他版本交给使用者确认。匹配度是排序分数，不代表已验证的准确率。

“在线搜索”可填写更精简的关键词，或 `https://lrclib.net/tracks/数字`、`https://lrclib.net/api/get/数字`。按 Enter 强制重新查询。重复点击线上匹配继续查看已经获取的后续候选，不声称 LRCLIB 支持分页。

## 稳定性

取消或重新搜索会中止旧请求并丢弃旧回调。每次请求超时十二秒。429 遵守 Retry-After 并停止后续请求；503 的短等待最多自动处理两次，精确接口繁忙时改走已排队的目录搜索，避免后台抓取器忙碌阻断整次查询。服务恢复前的再次点击会提示剩余等待时间。网络或数据格式错误会显示原因，不解释成“没有歌词”。

## 验证

本地 HTTP 测试覆盖标题清理、身份优先排序、去重、查询回退、503 等待与目录回退、429 冷却、取消以及直接歌词链接。

2026-10-24 真实联网验收：Yellow / Coldplay / 268 秒，成功取得 49 行现成时间轴，记录 ID 37471750。验证仅使用公开测试元数据，不使用用户歌曲，也不在报告保存歌词全文。详见 `live-lyrics-result.json`。

歌词覆盖取决于 LRCLIB 数据库；同名歌曲、翻唱、现场版可能需要确认。在线版没有音频配时模型，纯文字候选不能生成准确时间轴。

接口依据：[LRCLIB 官方 API 文档](https://lrclib.net/docs)。
