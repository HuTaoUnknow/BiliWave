# 下载入口与双语歌词（2026-10-22）

下载完成的任务保留，并在下排显示删除、收录、工作台三个图标。点击收录直接进入乐库；双击任务或点击工作台图标才会将该本地歌曲打开到独立工作台并切换页面；工作台位于左侧“播放”下面，包含歌词配置与识别队列。完成下载、选中搜索结果、URL 收录都不会自动打开工作台。歌曲源下拉框只包含通过这个入口打开过的本地歌曲。尚未入库的本地下载会在重新启动后恢复成完成任务，仍需点击打开。URL 歌曲直接入库，不加入工作台。取消下载自动移除，失败可以重试。

搜索框右边只保留搜索按钮。歌词匹配的两组选项靠左，右边留弹簧，选项区高度固定。工作台底部右侧为较小的“试听当前歌曲”和“识别字幕”；取消识别在右侧任务队列操作。“已导入乐库”显示在左侧导航下方空白区。

字幕范围窗口及设置增加英汉、俄汉、意汉双语选项。英汉复用中英模型；俄汉和意汉共用一次文字区域检测，再对相同文字框分别使用外语与中文识别器，按文字脚本与识别置信度选择结果。原有画面变化分段、中间帧识别和相似句合并保留，不增加逐帧 OCR。双语每个片段只创建一次检测结果，需要两个文字识别器时会增加相应推理量。CPU 和 GPU 均可用。

识别结果同时有外语和中文时保存为同一时间戳的两条标准 LRC 文本行；播放、工作台编辑时组合为一个时间点。外语显示左上，中文显示右下，不将中文当作下一句歌词。无字幕间隔沿用上一组两行，直到下一句出现；没有双语的歌曲仍显示当前句与下一句。导入同时间点的双语 LRC 同样适用。这是识别已有双语字幕，不会自动翻译单语字幕。

导入纯文本如果全部为交替的“外语原文 / 中文译文”两行一组，仅将外语原文交给音频对齐模型，中文沿用对应原文的时间。没有完整交替结构则按普通逐行歌词处理。请在提交前检查歌词顺序。

设置中可分别调整左上和右下的字号（10–96）、不透明度（0–100%）和颜色。右下水平、垂直位差以左上文字起点为基准，单位 px；默认水平 180、垂直 80。旧版当前句字号、颜色、透明度继续作为左上设置；右下初始采用旧版 65% 字号、半透明度，保存后各自独立。文字仍为纯色，无描边。

验证：

- `tests/core_tests.cpp` 覆盖同时间点配对、原文/译文顺序、导入导出保留、空白及普通重复时间点。
- `tests/redesign_tests.cpp` 覆盖下载完成不切换、箭头及双击打开、URL 不进入、底部按钮和提示位置；双语歌词实际播放到覆盖层，并检查独立颜色、透明度、位差及设置保存。
- `tests/create_bilingual_fixtures.py --verify` 使用原创英汉、俄汉、意汉字幕视频，分别运行 CPU 与 GPU 六组真实模型测试。结果见 `bilingual-ocr-validation.json`，每组 12 帧执行 2 次 OCR，原始检测区间为 0–2 s、3–5 s，显示区间按新规则延长为 0–3 s、3–6 s，不插入空白 LRC 行。对大小写、标点归一化后与原文一致。
- 俄语真实语音加入逐句中文译文后完成对齐，只向模型传入俄文，输出两组共享时间点、无警告，见 `bilingual-alignment-validation.json`。音频源及许可沿用 `RUSSIAN_ITALIAN.md` 的 FLEURS 记录。

测试字幕、测试音频仅保留在开发缓存，不加入用户乐库或发布媒体目录。

字幕分段与合并的最新判据、公式和复查修复见 `OCR_COMPARISON_REVIEW.md`。
